# Pre-registration 0001: Faber (2010), US sector relative strength

Written and committed before any result exists. Nothing in this file changes after it is committed. Any change is a new, dated amendment file that says why, and whether any result had been seen.

Paper: Faber, M. T. (2010), "Relative Strength Strategies for Investing", SSRN 1585517, First Draft April 2010.
Spec: specs/faber-2010.yaml at commit 4554c9f. Where this file and the spec differ, this file decides.

## 1. Data
- Kenneth French Data Library, "10 Industry Portfolios", monthly, the "Average Value Weighted Returns" table.
- Downloaded once, in step 5. Its SHA-256 and download date are recorded before any run.
- END is the last month in that file, fixed by the file before any run.
- Returns are in percent. A missing value (-99.99 or -999) inside a sample stops the run.
- The file is a newer vintage than the paper's, so small differences from the paper's numbers are expected. The tolerances in section 4 allow for this.

## 2. Strategy
- One version for each lookback L in {1, 3, 6, 9, 12} months and each holding count N in {1, ..., 9}: 45 versions.
- Signal at the end of month t: each sector's compounded return over months t-L+1 to t.
- During month t+1, hold the N highest-ranked sectors at equal weight, reset to equal weight every month. Ties go to the sector listed first in the file.
- No costs, taxes or slippage, as in the paper.
- Benchmark: the equal-weighted average of all ten sectors, rebalanced monthly.
- In-sample: holding months 1928-01 to 2009-12. After publication: 2010-01 to END.

## 3. Metrics
- CAGR: (product of (1 + r))^(12/T) - 1, for T months.
- Volatility: sample standard deviation (ddof = 1) of monthly returns, times sqrt(12).
- Sharpe, the paper's formula, used only to compare with the paper: (CAGR - 3.81%) / volatility.
- Max drawdown: the largest fall from a running peak of month-end values, starting from 1.
- Best and worst year: calendar-year compounded returns.
- Excess return: the monthly return minus the benchmark's in the same month. Annualised as the mean times 12.
- pp means percentage points.

## 4. Test 1: Reproduce (1928-01 to 2009-12)
Our numbers are compared with the paper's 180 strategy claims and its benchmark claims.
Tolerances (absolute difference): CAGR 0.50 pp, volatility 0.50 pp, Sharpe 0.03, max drawdown 2.0 pp, best and worst year 1.0 pp. Turnover is not tested.
Data check first: our benchmark CAGR and volatility must both be within tolerance. If either is not, the verdict is "inconclusive: data differ", and everything is still reported.
Verdict, from the 180 strategy claims:
- Reproduced: at least 162 (90%) within tolerance.
- Partly reproduced: 90 to 161.
- Not reproduced: fewer than 90.
Every claim's paper value, our value and the difference are reported, whatever the verdict.
Not tested: the paper's headline (beating the benchmark in about 70% of years). It appears to summarise Exhibit 4.6, the combined 1-3-6-9-12 lookback, which the spec leaves out. Each version's share of calendar years beating the benchmark is reported, without a verdict.

## 5. Test 2: After publication (2010-01 to END), run once
The family: the equal-weighted average of the 15 versions with N in {1, 2, 3}, across all five lookbacks. The paper spells out its rules for these holding counts (page 6). Using the family avoids choosing a favourite version after seeing results.
Statistic: the family's annualised mean excess return over the benchmark.
Estimator: Newey-West standard error with floor(4 x (T/100)^(2/9)) lags. One-sided test that the mean is above zero, with p from the normal distribution.
Verdict:
- Survived: p < 0.05.
- Weakened: estimate above zero, p >= 0.05.
- Gone: estimate zero or below.
Also reported, without a verdict: the same statistic in-sample; the ratio of after-publication to in-sample (for comparison, McLean and Pontiff (2016) found returns 58% lower after publication on average); and every version's after-publication numbers.

## 6. Test 3: Luck (in-sample and after publication)
Could picking sectors at random have done as well?
- A random family: for each of the 15 versions, each month pick N sectors uniformly at random, without replacement, at equal weight. Average the 15.
- Draw 10,000 random families with numpy.random.default_rng(20261106).
- p = (1 + the number of random families whose statistic is at least the real family's) / 10,001, using the statistic from Test 2.
- Run separately in-sample and after publication.
- Verdict for each sample: "beats luck" if p < 0.05, otherwise "not distinguishable from luck".

## 7. Sensitivity checks (reported, never change a verdict)
- Weights left to drift between rebalances instead of being reset to equal.
- Volatility with ddof = 0.

## 8. Conduct
- Before any run, the code must pass tests showing that no position uses data from its holding month or later.
- Order: Test 1; then Test 3 in-sample; then Test 2 and Test 3 after publication, in one run. Each verdict is recorded and committed before the next test runs.
- A bug found after a result has been seen is fixed, both results are reported, and the fixing commit is named.
- Nothing about the strategy, data, metrics, tolerances or verdict rules changes after any result is seen, except through a dated amendment that says which results had been seen.
- Every result file records the commit hash of this file.
- Costs, tradability, forward and live tests are not part of M1. Each gets its own pre-registration.
